# Raylight Editor — Consolidated Master Product, Architecture & Code Audit

- **Reviewed revision:** `7631176` (consolidating `08607da` audit + full-stack component/engine/UI audit)
- **Scope:** Complete shipped Vite/React/Three.js editor under `src/`, project docs (`README.md`, `PRODUCT.md`, `DESIGN.md`), build config, and 90 Vitest test suites.
- **Load assumption:** One person editing a local project in a modern desktop browser; projects may contain multiple shots, many 2D/3D layers, procedural device frames, post-processing shaders, and large embedded video/audio media.
- **UI direction:** Keep the editor ultra-clean, minimal, and Figma-inspired: canvas-first, minimal persistent chrome, with anything not actively in use tucked away into `+` section headers, 1-line summary pills, contextual dropdowns, and flyouts.
- **Method:** Line-by-line verification of every finding across both audits against live `src/` code, plus static/test/build/lint verification and benchmarking against Figma, After Effects, Blender, Rive, Screen Studio, and Spline.

## Executive Summary

Raylight has a strong architectural foundation: structured project data (`Project → Shots → Layers/Groups`), separated Zustand stores (`useProjectStore`, `usePlayheadStore`, `useSelectionStore`), transaction-aware undo/redo, deterministic evaluators, a 3D WebGL stage with procedural hardware mockups, a 2D Canvas renderer, Web Audio synthesis/playback, and dual `localStorage` + `IndexedDB`/`OPFS` persistence.

Combining both independent audits and verifying every claim against the live source code revealed **32 verified findings** across four categories:
1. **Playback, Evaluation & Render Parity Bugs (P0/P1):**
   - Audio clips starting after the playhead are never scheduled during normal playback, and the playback RAF loop runs forever when project duration is zero.
   - Video layers subtract shot-local `layer.inMs` from **global** `currentTimeMs` instead of `shotLocalTimeMs`, causing videos in Shot 2+ to jump/freeze, and `syncAndSeekAllProjectVideos` seeks all shots concurrently on shared `<video>` elements.
   - WebGL shot transitions crossfade/slide backgrounds ONLY, omitting outgoing layers and lights that the 2D Canvas renderer composites.
   - 7 selectable transition presets (`pop`, `spin`, `flip-x`, `flip-y`, `swing`, `wipe`, `scramble`) and non-typewriter text `stagger` are unimplemented no-ops in `evaluateLayer.ts`.
   - Resizing a rotated layer on the Stage uses unrotated screen deltas (`SelectionOverlay.tsx`), causing severe axis distortion.
   - Video export uses real-time `MediaRecorder` and explicitly skips frames under load (`exporter.ts`), while `seekVideoElement` resolves 600ms timeouts as success (silently exporting stale frames).
2. **Project Portability, Schema Integrity & Storage Durability (P1/P2):**
   - `.raylight.json` import/export helpers exist in `projectIO.ts` and are advertised in `README.md`, but have **zero callers** in the UI.
   - `validateProject` in `schema.ts` accepts duplicate IDs and unverified foreign keys (`groupId`, `maskLayerId`, `assetId`).
   - Autosave (`saveProjectToBrowser`) can silently lose media on reload if `localStorage` strips base64 on quota overflow and async `IndexedDB` fails, with no save-status UI.
   - Imported media has no byte/dimension bounds, uploads are read into RAM as base64 strings, and `figmaSvgImporter.ts` copies remote `<image href>` URLs directly into `asset.dataUrl`.
3. **Keyboard Operability, Accessibility & Shortcut Consistency (P1/P2):**
   - `Space` hijacks focused `<button>` and `<a>` elements because `isEditableElement` only checks text inputs.
   - Duplicate `keydown` listeners in `App.tsx` and `Stage.tsx` conflict with `CanvasToolbar.tsx` shortcut badges (`C` vs `S` for Scissors, `⇧F` vs `C` for Orbit), and `Delete`/`Backspace` ignores selected shots despite `README.md`.
   - Shot rows, timeline shot cards, and scene-light rows lack keyboard operability; ARIA `tablist`/`tab` components lack roving `tabIndex` and `tabpanel` links; hover-only actions (`opacity-0 group-hover:opacity-100`) can receive invisible keyboard focus; `ModalShell` lacks focus trapping and `aria-labelledby`.
4. **Performance Hot Paths & Figma-Style Minimal UI Transformation (P1/P2):**
   - `App.tsx` and `Timeline.tsx` subscribe to `currentTimeMs` at the root, re-rendering at 60fps during playback, and `App.tsx` tears down/re-binds its global `keydown` listener 60 times/sec because `frame.shotLocalTimeMs` is in its `useEffect` dependency array.
   - `useProjectStore` runs full-project synchronous Zod validation on every edit, undo, and redo; `ThreeLayerObject` allocates a new DOM `<canvas>` and `THREE.CanvasTexture` on every animated blur/shimmer/text tick; `SceneEffectsPipeline` re-runs pass setup every frame because `evaluateEffects` returns fresh object references.
   - Inspector sections (`LayerGeometrySections`, `LayerEffectsSection`, `LayerAnimateInspector`, `CameraBlockSection`, `ProjectSettingsPanel`) render multi-row expanded cards inline instead of compact 1-line Figma rows with `+` headers and flyout popovers.

## Detailed Findings by Domain

### 1. Playback, Timebase, Evaluation & Render Parity (F-01, F-02, F-03, F-13, F-14, F-15, F-21, F-23, F-24, F-25, F-26)

1. **[F-01 | P0] Audio Scheduler Skips Future Clips & Empty Project RAF Loops Forever**
   - **Evidence:** [`audioEngine.ts:189-225`](file:///c:/Users/Sam%20Akinkunmi/Downloads/Ray_New/raylight-editor/src/engine/audioEngine.ts#L189-L225), [`App.tsx:412,455`](file:///c:/Users/Sam%20Akinkunmi/Downloads/Ray_New/raylight-editor/src/App.tsx#L412).
   - **Cause:** `syncAudioPlayback` only starts clips where `currentTimeMs >= clip.startMs && currentTimeMs < clip.endMs` when `playStateChanged` or `playheadJumped` is true, then updates `lastSyncedTimeMs = currentTimeMs` every frame so `playheadJumped` is always `false` during normal playback. Clips starting after the playhead are never scheduled. Meanwhile, `App.tsx:455` checks `if (next >= totalDurationMs && totalDurationMs > 0)`, so a zero-duration project runs `requestAnimationFrame` indefinitely.
   - **User Effect:** Sound effects or music clips placed after the initial playhead position are completely silent during playback; an empty project stays in a playing state burning CPU.

2. **[F-02 | P0] Video Layer Timebase Bug (Global vs. Shot-Local Time) & Shared Video Seek Contention**
   - **Evidence:** [`ThreeLayerObject.tsx:330`](file:///c:/Users/Sam%20Akinkunmi/Downloads/Ray_New/raylight-editor/src/stage/webgl/ThreeLayerObject.tsx#L330), [`canvasRenderer.ts:167-189,1093`](file:///c:/Users/Sam%20Akinkunmi/Downloads/Ray_New/raylight-editor/src/engine/canvasRenderer.ts#L167-L189), [`evaluateShot.ts:260`](file:///c:/Users/Sam%20Akinkunmi/Downloads/Ray_New/raylight-editor/src/engine/evaluateShot.ts#L260).
   - **Cause:** `layer.inMs` is authored in **shot-local time** (`0..shot.durationMs`), which is how `evaluateLayerAtTime(layer, shotLocalTimeMs)` evaluates visibility and animations. However, `ThreeLayerObject.tsx:330` computes `(currentTimeMs - layer.inMs) / 1000` using **global project time**, and `syncAndSeekAllProjectVideos` in `canvasRenderer.ts:179` loops over *every shot in the project* computing `(timeMs - layer.inMs) / 1000` on shared `<video>` elements (`getOrCreateVideoElement(asset.dataUrl)`).
   - **User Effect:** Any video placed in Shot 2 or later seeks to the wrong timestamp (jumping ahead by `shot.startMs`), or freezes past its end; if two shots use the same video asset, export seeks overwrite each other.

3. **[F-03 | P0] WebGL Shot Transitions Omit Outgoing Layers & Lights (WebGL vs. Canvas Parity Failure)**
   - **Evidence:** [`ViewportCanvas.tsx:237-272`](file:///c:/Users/Sam%20Akinkunmi/Downloads/Ray_New/raylight-editor/src/stage/webgl/ViewportCanvas.tsx#L237-L272), [`SceneBackground.tsx:492-535`](file:///c:/Users/Sam%20Akinkunmi/Downloads/Ray_New/raylight-editor/src/stage/webgl/SceneBackground.tsx#L492-L535), [`canvasRenderer.ts:1115-1145`](file:///c:/Users/Sam%20Akinkunmi/Downloads/Ray_New/raylight-editor/src/engine/canvasRenderer.ts#L1115-L1145).
   - **Cause:** During a shot transition (`crossfade`, `push`, `slide`), `evaluateShotAtTime` populates `frame.shotTransition.outgoingFrame`. `canvasRenderer.ts` composites `outgoingFrame.layers` and `outgoingFrame.activeShot.light` with `outgoingOpacity` and `outgoingSlideX`. `ViewportCanvas.tsx` transitions `SceneBackground`, but only mounts `frame.layers` (incoming) — never `outgoingFrame.layers`!
   - **User Effect:** In the live WebGL stage (and WebGL stage-capture exports), outgoing layers vanish abruptly at the start of a transition instead of crossfading or sliding out.
