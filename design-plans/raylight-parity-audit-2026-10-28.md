# Raylight Editor parity audit

- **Date:** 28 October 2026
- **Reference:** `https://www.raylight.app/editor/fcf48dd2-642b-4fe4-a893-eaacf09c9e08`
- **Local app:** `http://localhost:3000/`, repository revision `99f7bf79c98e179d723ad2f38e7ffd4733e3d2d1`
- **Scope:** End-to-end editor shell, layer tree, canvas, tools, object inspector, solid and gradient color workflows, camera/orbit/zoom, timeline, assets, animation, lighting/effects, project settings, export/share, keyboard interaction, and rendering.

> **Phase 2 audit correction (28 October 2026):** Source inspection after this audit found that the described on-canvas gradient angle control was wired only to the resolved scene background. Shape ColorPicker callbacks did not activate it. Phase 2 now adds a selected-shape target and routes angle changes to that shape fill; the earlier parity summary should not be read as evidence that layer-angle editing existed before this correction.
- **Method:** Direct visual/interaction inspection of the provided reference project and the running local app; source tracing for local ownership and capability; checked `DESIGN.md`, `PRODUCT.md`, and the existing audit report. The reference project was inspected read-only. The local project was not edited. No tests were run for this audit.

## Executive summary

The local app is a capable motion editor with several areas that match or exceed the reference: WebGL stage, layer hierarchy, design/animate inspector tabs, color sampling support, an interactive gradient stop rail, on-canvas gradient angle editing, trackball orientation gizmo, camera pan/orbit/dolly gestures, multiple timeline track types, snapping, shot trimming/reordering, and local MP4/GIF export.

The clearest parity gap is **gradient authoring**. The reference picker exposes Linear, Radial, Angular, Diamond, and Mesh gradients and puts Blend mode in the color popover. The local layer-fill picker exposes only Linear and Radial and does not expose blend mode in that popover. Local project background shaders include mesh-style presets, but those are a different workflow from editable layer-fill gradient types.

The local camera controls are functionally rich, but the camera workflow differs: the reference Orbit mode exposes a contextual Angle menu with seven named angles plus Pin and Back to camera. The local app has four quick views (Front, Top, Right, Iso), a reset button, Frame Scene/Selection, and a drag-enabled orientation trackball; the viewport camera tool uses C and gestures rather than the reference's Shift+F Orbit entry and contextual controls.

The prior reported “rectangle invisible but handles visible” issue was not reproduced in the inspected local session: the selected rectangle rendered with its blue gradient fill and selection handles. The fix committed at `99f7bf7` appears present in this observed state.

## Design language

- **Audited surface:** The local Vite/React editor at `/`—the canvas workspace, left File/Assets panel, timeline, floating canvas toolbar, and right inspector.
- **Design sources:** `DESIGN.md` and `src/index.css`; `PRODUCT.md` documents product intent and feature scope. The reference site is used as the requested product benchmark, not as a local design-system specification.
- **Documented decisions:** “Viewport Artifact Primacy”; compact precision panels; tokenized dark studio surfaces; blue primary/selection states; Inter UI text and tabular monospaced dynamic values; pointer-driven canvas/timeline manipulation.
- **Governing owners and consumers:** `App.tsx` composes `LeftPanel`, `Stage`, `Timeline`, and `RightSidebar`; `Stage.tsx` owns canvas tools/gestures; `OrientationGizmo.tsx` owns the camera HUD; `ColorPicker.tsx` owns solid/gradient editing; `Timeline.tsx` owns shot/layer/camera/light/key bars; `useProjectStore` and `useSelectionStore` own document and UI state.
- **Explicit exceptions:** None documented.

## Recommended follow-up order

1. Align layer-fill gradient capabilities with the reference: decide whether Angular, Diamond, and Mesh are required for shape/text/image fills; then extend the model/schema/renderer and picker together. Keep the local gradient stop rail and on-canvas angle editing.
2. Bring camera views and orbit-mode actions to parity: add the named cinematic viewpoints and explicit pin/back-to-authored-camera controls if those actions exist in the reference contract. Reconcile shortcut labels and gestures in the shortcut dialog.
3. Decide whether Pen, Comment, and Frame are part of the intended local product. If yes, expose working canvas tools and represent their output/state in the document model; Pen already creates polygon path layers via `P`, but needs a discoverable toolbar entry if retained. Comment and creation Frame were not found; do not conflate Frame with camera framing.
4. Revisit the default inspector width against the documented canvas-first goal; preserve its resize handle and make the default adapt to viewport width.
5. Repeat timeline comparison using equivalent multi-shot projects with animated layers, camera/light blocks, audio/video clips, and transitions. Capture each bar’s select/move/trim/snap behavior and playhead semantics before calling timeline parity complete.

## Audit limits

This was a deep comparative inspection of the visible editor surface plus local source tracing, not a full protocol/network reverse engineering of Raylight’s private services. Reference behavior was only interacted with where it remained read-only (tool menus, picker mode/type menus, tool mode); no document property or export/share operation was changed or submitted. The local Share handler was opened, but no export was run and no share link was sent. Several reference claims above intentionally say “not verified” rather than inferring behavior from a single project screenshot. Complete parity needs matched project fixtures and repeatable interaction runs across asset import, save/reload, animation evaluation, playback, and export.

### Newly verified interaction gap: Share button

In the local right-sidebar source, Share set a toast state that changed the label to “Copied!” and immediately opened the Export modal; no clipboard write or share-link generation occurred. Phase 1 resolves this by labeling the action “Export,” routing directly to the existing export modal and removing the false success toast. The reference Share flow remains unverified.

### Coverage boundary

“Click all the clickables” cannot be completed literally without altering the user’s project, granting browser sampling, uploading assets, replacing/importing the document, downloading exports, or sending a share. Those actions were traced and their setup/options inspected, but not committed. The reference is a populated project and only safe navigation/picker/tool interactions were used. This audit covers the listed component inventory and exposed controls at source/UI level; it does not claim exhaustive private-service/network reverse engineering, all responsive sizes, all error states, or matched-fixture rendering parity. The first audit’s appendix has now been expanded, and its stale statement that project JSON actions are absent is superseded: current local project menu exposes Import Project File and Export Project (.raylight.json).
